You are reviewing a round of work on the {name} project (root: {root}) — the sweep is the iteration's turn: fired whenever a round of work reaches a review point (day's end is only the degenerate case). A sweep is NOT a daily event — it may fire several times in one day, and finding the queue already stocked or a session log already present from an earlier pass today is normal, not an error or a sign the work is done. Each sweep is its own pass over the current queue state.

DESIGN OF THIS PASS — two jobs with different costs:
  CLOSE  — commit the sitting (rulings, comments, ripples). Keep this cheap when little changed.
  ACCRUE — deepen project familiarity and restock the next batch. This is where time should go:
           honest briefs and a better map of the project for future sittings.
All of this happens in one pass, visibly, but do NOT perform ceremony when there is nothing to close. Prefer tool calls that serve ACCRUE over re-deriving diffs the desk already computed.

=== CLOSE ===
1. RULINGS — if a ruling ledger is configured ({ledger}): apply every ticked/filled/struck ruling to its canonical documents exactly as written; annotate each applied row '— swept {today}'; never infer rulings; launch-type rulings (a 'go', a grant, an acquisition, a schedule) are NOT executed — append 'LAUNCH DIRECTIVE: <what>' to {runtime_dir}/sweep.log AND stage a desk egress memo (`setsweep egress <project> --kind launch --topic <slug>` or write under {desk_dir}/outbound/) so pickup has one folder to drain.
1b. BALLOTS — a persona's `QUESTIONS.md` (an `ask_type: fill` entry) carries the Dramaturge's casting questions as checkboxes; a ticked box is the patron's ruling. For each tick: if it CONFIRMS the persona's current chief/cast, mark it resolved, clear that question from the file, annotate '— swept {today}'. If it CHANGES the cast (a different chief, a figure kept/cut/re-weighted, a write-in), that is a RECAST that belongs to the Dramaturge, never the desk: raise it as a memo to {root}/Characters/inbox/ (and record it) AND stage a short `kind: domain` egress pointer under {desk_dir}/outbound/ — do NOT recast the persona BODY/SOURCES from the desk (the standing guardrail). Either way, learn the standing casting preference into MEMORY so the question is not re-asked.
2. DIFF — use the PRECOMPUTED DIFFS block below (already computed against {runtime_dir}/snapshots/<id>.orig). Do NOT re-run `diff -u` unless a listed entry says the precompute is missing. Read the PATRON COMMENTS block: for each entry, surface matching comments as binding direction BEFORE you assess that file — same weight as inline edits.
2a. QUIET CLOSE — if EVERY entry is byte-identical to its snapshot (or has no snapshot and no file change to assess), carries no patron comment (PATRON COMMENTS block or entry `comment` field), and the ledger shows no fresh ruling: skip assess/ripple/preference-write for those entries. Still proceed to ACCRUE+RESTOCK unless this is an inbox project whose override says otherwise. A full STOP ('nothing to sweep since the last pass') applies only when the queue was already archived and there is also nothing to restock — not when approved entries still need archive+restock after a quiet sitting.
3. ASSESS — only for entries with a non-empty diff, a patron comment, or a ledger ruling: 1–2 sentences on what changed and apparent intent. Skip 'unchanged, approved as-is' essays.
4. RIPPLE — only when assess found something that could propagate: check the project for stale cross-references, contradicted statements, renamed terms. FIX mechanical issues in place; FLAG judgment in the log. A patron comment naming a rename makes propagation REQUIRED. Never touch append-only records.
5. PREFERENCES — update {desk_dir}/MEMORY.md ONLY if this sitting produced a standing preference or ruling that must not be re-asked (compare briefs' predictions to what the patron did). If nothing generalizes, leave MEMORY.md untouched — do not invent thin process notes. Terse dated bullets when you do write; keep under ~80 lines; revise/strike contradicted entries; if evidence contradicts PROJECT.md, amend it minimally and note that in MEMORY.
6. LOG — write {runtime_dir}/sessions/{stamp}-session.md (unique stamp; never overwrite an earlier pass). Default shape is THIN: one line per entry (id — unchanged-approved | comment acted | ripple fixed | flagged: …). Expand to a short paragraph only for judgment flags, multi-file ripples, or memos raised. If a domain memo or desk egress file already carries the substance (e.g. Characters/inbox, {desk_dir}/outbound/), point at it — do not restate it. Include each patron comment verbatim only when you acted on or deferred it.
