# Familiarity framework

`FAMILIARITY.md` is project-centered expertise. It compounds across restocks so briefs improve over time. It is **not** patron preferences (those live in `MEMORY.md`) and **not** a sitting transcript (session logs).

## Suggested shape (adapt; keep under ~120 lines)

```markdown
# Familiarity — <project>

## Map
- Document families and what each is for
- Key paths (collections, indexes, entry points)

## Relationships
- What depends on what; single sources of truth

## Pitfalls
- Recurring false alarms, format traps, “don’t re-raise” structural facts
  (prefs/rulings still go in MEMORY.md)

## Brief craft
- What “good review” looks like on this desk; lenses that worked
```

## Update rules

- Read familiarity **before** drafting restock briefs.
- After reading new files, add only durable knowledge (or correct staleness).
- If nothing new about the project, leave the file untouched.
- Strike or revise map entries the corpus no longer supports.
